## 3. Consequences

- **Timestamp provenance (L-01) is answered for live operation.** Historical
  `dataset_time` is broker server time, not UTC. The Phase E results are
  unaffected in substance (that variant isolated sessions), but any
  session-dependent research must convert time — see Phase G.
- **Monetary sizing remains blocked** until the owner confirms the economics
  (`config/broker_expectations.json`). The implementation
  (`runtime/risk.py::size_position`) is complete and tested; it also refuses
  without a verified commission figure and cross-checks every size against the
  broker's own `order_calc_profit`.
- **At 1% risk on a 10,000 USD account** a 10.00 stop allows 0.09 lots → 0.08
  after even-step rounding (both halves ≥ 0.01). Small accounts or wide stops
  will often fail the "minimum volume within risk" rule; that is the intended
  fail-closed result.
- **Stops level 10 points** is far below typical structural stop distances
  (several dollars), so stop placement is not expected to conflict; a demo
  adapter must still re-check it per order.

## 4. Owner confirmation procedure

1. Open `state/broker_expectations.proposed.json` (regenerated by every verification).
2. Compare each value with Fortune Prime's published XAUUSD-P specification and
   an account statement.
3. Save as `config/broker_expectations.json` with `"source"` naming the document
   and `"confirmed_by_owner": true`.
4. Re-run `python -m trantor.runtime verify-broker`; the overall status becomes
   `economics_verified` only if every live value still matches.
